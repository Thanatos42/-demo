## 简介
本指南面向希望在现有奶茶店模拟经营 Demo 基础上进行功能扩展的开发者。你将学会如何添加新的奶茶配方、扩展原料选项、自定义 UI 样式，并理解代码结构与扩展点（枚举、配置参数、UI 组件）的位置与用法。文档同时提供最佳实践、命名规范、组织原则以及测试与调试方法，帮助你安全、高效地迭代功能。

**重要更新**：项目已从纯代码动态构建UI升级为预制体/场景驱动架构，支持更丰富的动画效果和UI组件管理。

## 性能与可维护性建议
- **避免动态UI创建**：新项目应优先使用预制体和场景构建方式，减少运行时开销。
- **利用标记组件**：通过轻量级标记脚本实现自动接线，降低硬编码依赖。
- **集中动画管理**：将动画逻辑集中在控制器中，便于统一管理和调试。
- **配置驱动**：将易变配置（颜色、字体、尺寸）集中在美术库资产中，便于策划调整。
- **增量构建**：利用场景构建器的增量构建特性，保护手动调整的UI布局。

## 故障排查指南
- **中文显示异常**：字体创建失败会回退到内置 Arial，建议在美术库中引入中文字体资源。
- **UI无响应**：确保场景中有 EventSystem；检查标记组件是否正确添加到UI元素上。
- **动画不播放**：检查 VideoPlayer 是否正确配置；确认 SpriteSequenceAnimator 已正确挂载。
- **配方始终判定错误**：检查提交校验逻辑与期望值是否一致；确认糖度/冰度等级与选项映射是否正确。
- **解锁状态未生效**：确认 PlayerPrefs 键名未被覆盖；可在编辑器控制台打印或临时读取验证。

## 结论
本项目采用"编辑器构建 + 运行时控制"的现代架构，通过预制体和标记组件实现了更好的可维护性和扩展性。新增的动画系统集成和增强的UI组件管理机制，使得开发者可以专注于业务逻辑而无需关心底层UI创建细节。基于现有结构，你可以轻松扩展配方、原料与 UI 主题，并通过数据驱动的方式最小化改动范围。

### 8) 最佳实践与命名规范
- **命名规范**：
  - 变量与方法使用驼峰命名；私有成员以下划线前缀区分。
  - 枚举值使用语义化名词，避免缩写。
  - 标记组件类名以功能描述命名，如 MilkTeaChoiceButton。
- **代码组织**：
  - 将 UI 构建、交互、状态管理分方法拆分，保持单一职责。
  - 将易变配置集中放置，便于统一修改。
  - 使用 ScriptableObject 管理游戏数据，便于策划编辑。
- **扩展原则**：
  - 优先通过数据驱动（数组/字典）扩展内容，而非复制粘贴逻辑。
  - 新增功能尽量向后兼容，避免破坏已有流程。
  - 使用标记组件机制解耦UI和业务逻辑。
